# Pluggable themes: design

Status: implemented (2026-11-28).

## 1. Intent

Today every report generated by `ledger` (`manager_`, `dm_`, `person_`) uses a single hardcoded stylesheet in `ledger/render.py`. Delivery managers supplying engineers to different customers — or reporting inside a branded enterprise — often have a folder or file of brand/style assets (a Markdown `style-guide.md`, company logos, colour tokens, CSS snippets, and tone-of-voice rules) and want the customer-facing `manager_` report (and optionally `dm_` and `person_`) styled accordingly.

Pluggable themes keep this as simple as it gets: configure **one path** where style assets live in `config.json` (or override per run with `--theme`). `ledger` stays 100% deterministic, offline-safe, and stdlib-only (reading only CSS and a small JSON manifest), while the agent interprets any Markdown style guide, prepares a local theme snapshot when needed, and applies editorial/tone guidance when proposing report highlights.

## 2. Goals, non-goals, anti-goals

- **Goals:**
  - Configure one `"theme"` path in `config.json`, overridable per run with `--theme PATH` or disabled with `--theme none`.
  - Apply themes to `manager_` by default, with `"theme_reports"` allowing opt-in for `"dm"` and/or `"person"`.
  - Support both ready-made theme inputs (a `.css` file, or a folder containing `theme.css` and/or `theme.json`) **and** raw style-asset paths (a Markdown style guide or brand folder) without mutating the user's source folder, via one local prepared snapshot in `<dir>/theme/`.
  - Support light, offline-safe branding chrome (`logo`, `logo_alt`, `header_note`, `footer_note`) alongside CSS token overrides, custom rules, and `@media print`.
  - Document the agent workflow in `skills/delivery-report/SKILL.md` and `AGENTS.md` so the agent prepares `<dir>/theme/` from raw style assets (with DM confirmation) and follows Markdown prose/voice rules when proposing `## Summary` / `## Exec note` text.
  - Keep every report self-contained single-file HTML (inline CSS, base64 data-URI `<img>` logo, zero `<script>`, no external runtime asset loads).
  - Preserve today's visual output and zero-config behaviour when no theme is active, and stay within the 4,600-line codebase cap in `tests/test_size.py` as the initial acceptance criterion.
- **Non-goals:**
  - Calling an LLM, parsing Markdown, or auto-compiling style guides inside the `ledger` Python CLI.
  - Automatic freshness tracking (hashes, timestamps, file watchers) for prepared snapshots.
  - Arbitrary HTML template replacement or section reordering (report structure, metrics, and footnotes stay fixed and auditable).
  - Per-team themes inside a single multi-team report.
  - Interactive theme prompts during `ledger init` (setup stays minimal per `docs/design-v3.md`).
  - External stylesheets, remote web fonts, or CSS `url(...)` asset dependencies in v1.
  - Dark-mode toggle (`color_scheme`) in `theme.json` (reports remain light by default; a `theme.css` may still write its own palette if desired).
- **Anti-goals:**
  - Mutating an external/shared brand folder unless the DM explicitly asks.
  - Silently applying a prepared snapshot after `"theme"` or `--theme` switches to a different source path.
  - Theme loading or validation failing after `notes.md` or HTML writes begin.
  - Weakening the `manager_` roster-name warning scan with overly broad regex filtering.
  - Treating `theme.css` as untrusted sandboxed input with brittle `!important` wars or a custom CSS sanitizer — themes are **trusted local presentation code**.

## 3. Configuration and CLI

### `config.json`

```json
{
  "theme": "/abs/path/to/brand-assets",
  "theme_reports": ["manager"]
}
```

- **`theme`** (optional `str`, default `""`): path to a `.css` file, a ready-made theme folder, or a raw style-assets file/folder (e.g. a Markdown style guide or brand kit directory). Relative paths resolve against `--dir` (`.delivery-skills/` by default); `~` is expanded via `os.path.expanduser`. Empty string `""` or omitted means no theme. `"none"` is reserved for the CLI and is not special in `config.json`.
- **`theme_reports`** (optional `list[str]`, default `["manager"]`): which report types receive the active theme. Valid entries: `"manager"`, `"dm"`, `"person"`. An empty list `[]` is valid and disables theming without removing `theme`.

### Validation in `load_config()` and `run_init()` lifecycle

- `theme` (when present): must be a `str` (reject `null`, booleans, numbers, lists, dicts with `ValueError`). Path existence is checked only when a command actually needs the theme (matching `vacations`).
- `theme_reports` (when present): must be a `list` of unique `str` entries, each in `{"manager", "dm", "person"}`; malformed entries, unknown names, duplicates, or `null` raise `ValueError` (same pattern as `manager_metrics`).
- `run_init()` already loads and saves the existing `Config` object, so `theme` and `theme_reports` are preserved automatically (covered by a regression test); `init` adds no prompts.

### CLI flag (`--theme`)

Added identically to both `report` and `person` in `ledger/cli.py`:

```sh
bin/ledger report [--sprint S] [--offline] [--today YYYY-MM-DD] [--theme PATH|none]
bin/ledger person EMAIL [--offline] [--today YYYY-MM-DD] [--theme PATH|none]
```

- `--theme PATH`: overrides `cfg.theme` for that run. Relative CLI paths resolve against `os.getcwd()` (with `~` expanded).
- `--theme none` (case-insensitive): disables any configured theme for that run (no theme filesystem access occurs).
- **Identical target rules on both commands:**
  - `--theme` only overrides the theme path; `cfg.theme_reports` selects which report targets receive it (`manager` / `dm` for `report`; `person` for `person`).
  - If no target for the current command is enabled in `cfg.theme_reports`, skip theme filesystem access completely. If `--theme PATH` (non-`none`) was explicitly passed in that case, emit a warning naming the excluded target(s) (`theme_reports excludes ...; --theme has no effect on this command`).

## 4. Theme resolution and prepared snapshot

### Failure boundary

Both `run_report()` and `run_person()` determine the command's enabled theme targets and load/validate the complete theme **once, before** mutating `notes.md` or writing any HTML file. Any theme-related `OSError` (unreadable file, permission error, a directory named `theme.css`, etc.) is converted into a contextual `ValueError` so `cli.py` prints `error: ...` cleanly with zero partial writes and no traceback.

### Resolution rules (`load_theme`)

Given `raw_path`, `base_dir` (`--dir` for `config.json`, `os.getcwd()` for `--theme`), `work_dir` (`--dir`), and `warn`:

1. If `raw_path` is empty (or CLI `--theme none`) → return `None`.
2. Resolve the configured path against `base_dir`:
   `expanded = os.path.expanduser(raw_path)`
   `resolved = os.path.abspath(os.path.join(base_dir, expanded))`
   `canonical = os.path.realpath(resolved)`
3. If `resolved` does not exist → `raise ValueError(f"theme path not found: '{raw_path}'")`.
4. **Ready-made inputs (used directly, never overridden by `<work_dir>/theme/`):**
   - **`.css` file** (`os.path.isfile(resolved)` and `.css` extension, case-insensitive): load CSS directly from `resolved`.
   - **Ready-made theme directory** (`os.path.isdir(resolved)` containing `theme.css` and/or `theme.json`): load `theme.css` (if present) and `theme.json` (if present) directly from `resolved`. Logo paths in `theme.json` resolve strictly inside `resolved`.
5. **Raw style-asset inputs (anything else — e.g. a `.md` style guide or a brand folder without `theme.css`/`theme.json`):**
   - `ledger` never parses Markdown or guesses CSS from raw assets.
   - Look for a **prepared snapshot** at `<work_dir>/theme/`:
     - If `<work_dir>/theme/theme.json` exists, parse it and check its `"source"` field (must be a non-empty absolute path; compare `os.path.realpath(source)` against `canonical`).
     - If `"source"` matches `canonical`: load `<work_dir>/theme/theme.css` (if present) and `<work_dir>/theme/theme.json`. Any `logo` in `theme.json` must live inside `<work_dir>/theme/` (copied there by the agent when preparing the snapshot — single asset root, no cross-directory fallback).
     - If `<work_dir>/theme/theme.json` exists with a missing, relative, or non-matching `"source"`: emit `warning: prepared theme in <work_dir>/theme does not match '<raw_path>'; using default styling` and return `None`.
     - If `<work_dir>/theme/theme.json` does not exist: emit `warning: theme '<raw_path>' has no prepared theme in <work_dir>/theme yet; using default styling` and return `None`.
   - Malformed files in a selected theme (invalid `theme.json`, missing/oversized/escaping logo, `</style` breakout in `theme.css`, unreadable file) always raise `ValueError`.

**Freshness contract:** `<work_dir>/theme/` is an explicitly **prepared snapshot**, not an automatically maintained cache. A matching `"source"` proves only which source path it was prepared for; edits to the source style guide take effect when the agent prepares `<work_dir>/theme/` again.

## 5. Theme contract (`theme.css` and `theme.json`)

### CSS token contract

Built-in `CSS` in `ledger/render.py` exposes these `:root` custom properties (with today's exact visual values as defaults):

| Group | Tokens | Default |
|---|---|---|
| Surfaces & ink | `--bg`, `--paper`, `--fg`, `--muted`, `--line` | `#F6F7F9`, `#FFF`, `#16202A`, `#5A6573`, `#DCE1E7` |
| Brand accent | `--accent`, `--accent-soft` | `#1E5B86`, `#E6EEF5` |
| Semantic status | `--good`, `--good-soft`, `--warn`, `--warn-soft`, `--bad`, `--bad-soft` | `#2C7A4B`/`#E5F2EA`, `#9A6514`/`#FBF0DC`, `#A8352D`/`#F8E4E2` |
| Flow bar remainder | `--other` | `#B8C0CA` (used via `var(--other)` in `_flow()`) |
| Typography | `--font`, `--font-heading`, `--mono` | `system-ui,-apple-system,"Segoe UI",Roboto,sans-serif`; `var(--font)`; `ui-monospace,Menlo,Consolas,monospace` |
| Geometry | `--radius-card`, `--radius`, `--max-width` | `8px`, `6px`, `980px` |

### Stable DOM hooks

- Page scope: `body.report-manager`, `body.report-dm`, `body.report-person`.
- Brand chrome (rendered only when supplied by the active theme): `.brand-head`, `.brand-logo`, `.brand-header`, `.brand-footer`.
- Existing report hooks: `.wrap`, `.squad`, `.top`, `.meta`, `.cap`, `.note`, `.figs`, `.fig`, `.fig.key`, `.n`, `.l`, `.d.up`, `.d.down`, `.flow-bar`, `.tbl`, `.id`, `.chip`, `.GREEN`/`.green`, `.AMBER`/`.amber`, `.RED`/`.red`, `.wait`, `.track`, `.grey`, `.carry-empty`, `.foot`, `.private`, `details`, `summary`.
- Print rules: `theme.css` may include `@media print { ... }`.

### Manifest (`theme.json`)

Optional UTF-8 JSON object (required inside `<work_dir>/theme/` so `"source"` can be verified):

```json
{
  "source": "/abs/path/to/brand-assets",
  "logo": "logo.svg",
  "logo_alt": "Acme Corp",
  "header_note": "Confidential — Executive Delivery Review",
  "footer_note": "Prepared by Delivery Management"
}
```

| Field | Type | Default | Behaviour |
|---|---|---|---|
| `source` | `str` | `""` | Canonical absolute path to the source style assets; required when loaded as a `<work_dir>/theme/` prepared snapshot, optional metadata in a ready-made pack. |
| `logo` | `str` | `""` | Relative path inside the selected theme directory to `.svg`, `.png`, `.jpg`, `.jpeg`, or `.webp`. Embedded as base64 `data:<mime>;base64,...` inside `<img class="brand-logo">`. |
| `logo_alt` | `str` | `""` | HTML-escaped `alt` attribute for `.brand-logo`. |
| `header_note` | `str` | `""` | Plain text (HTML-escaped), rendered as `<p class="brand-header">`. |
| `footer_note` | `str` | `""` | Plain text (HTML-escaped), rendered as `<p class="brand-footer">` at the end of `.foot`. |

Unknown keys in `theme.json` emit a `warning:` naming them and are ignored. Invalid JSON, non-object root, or non-string field values raise `ValueError`.

### Trust model and safety guardrails

- **Trusted local presentation code:** `theme.css` is authored locally by the DM or their agent. `ledger` preserves all report data, structure, and warning markup (including keeping `.private` first in DOM), while theme authors are responsible for preserving visibility and semantic meaning of `.private`, RAG chips, delta arrows, and `@media print` output.
- **No `<style>` breakout:** CSS containing `</style` (case-insensitive) raises `ValueError`, protecting HTML integrity and `link_ids()`.
- **Offline self-containment:**
  - External stylesheets (`@import`) and non-`data:` `url(...)` references (including both `http(s)://` and relative `url(logo.png)`, which break once CSS is inlined into a report HTML file) are unsupported in v1. After stripping `/* ... */` comments, `ledger` emits a `warning:` if `theme.css` contains `@import` or a `url(...)` whose target does not start with `data:`.
  - Themed pages also include `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'; img-src data:;">` in `<head>` **before `<style>` and all resource-bearing markup** so browsers enforce no scripts and no external network loads while allowing inline styles, data-URI images, and normal `<a href>` links to Azure DevOps.
- **Safe logo embedding:**
  - Reject absolute paths, URL schemes (`http:`, `https:`, `data:`), `..` or symlink escapes outside the selected theme directory (verified via `os.path.realpath` + `os.path.commonpath`), unsupported extensions, missing files, and files larger than **512 KB** (`ValueError`).
  - Always render via `<img class="brand-logo" src="data:..." alt="...">` — never raw inline `<svg>`. Because SVG-as-image disables scripts and external subresources in browsers, any SVG logo must be self-contained.
- **No raw HTML in `theme.json`:** `logo_alt`, `header_note`, and `footer_note` are always HTML-escaped.
- **Name-leak scan hygiene (`run_report()`):**
  - Before calling `unescape()`, remove only the single generated `<style>...</style>` block and the exact generated `<img class="brand-logo" src="data:...">` `src` payload (leaving `alt`, `header_note`, `footer_note`, and all visible text — including literal text like `data: Maya Brook` or escaped `&lt;style&gt;Maya Brook&lt;/style&gt;` — intact for scanning).
  - Scope note: the roster-name warning scans report text and attributes, not lettering drawn inside images or CSS `content:`. Theme authors must not put engineer names in logos or CSS `content:`.

## 6. What the reader sees

- **When no theme applies to a report (`theme is None`):**
  - No `.brand-head`, `.brand-logo`, `.brand-header`, or `.brand-footer` markup is emitted, no theme CSS is appended, no CSP tag is added, and dark media queries remain stripped. Visual output is identical to today.
- **When a theme applies to `manager_`, `dm_`, or `person_`:**
  - `<body>` carries `class="report-manager"`, `class="report-dm"`, or `class="report-person"` (emitted consistently across unthemed and themed renders).
  - Theme CSS is appended inside `<style>` after `CSS` (and after `MANAGER_CSS` on `manager_`).
  - Header layout (shared across `_head()` for `manager_`/`dm_` and the header builder in `render_person()` for `person_`):
    - On `dm_` and `person_`, the `.private` banner always remains first in DOM, above `.brand-header` and `.brand-head`.
    - If `header_note` is set: `<p class="brand-header">...</p>`.
    - If `logo` is set: `<div class="brand-head"><img class="brand-logo" src="data:..." alt="..."><h1>...</h1></div>` (with minimal built-in CSS `.brand-head{display:flex;align-items:center;gap:14px;flex-wrap:wrap}.brand-logo{max-height:36px;width:auto;display:block}` only when a logo is present, overridable by `theme.css`).
    - Otherwise `<h1>...</h1>` renders directly as today.
  - Footer layout (both `_footnote()` and `render_person()`'s `.foot` div):
    - If `footer_note` is set: `<p class="brand-footer">...</p>` is appended inside `.foot`.
  - All figures, tables, chips, folded panels, `#ID` links, and method footnotes stay unchanged.

## 7. Agent workflow (`skills/delivery-report/SKILL.md` and `AGENTS.md`)

Add a concise **Themes and style guides** section to `skills/delivery-report/SKILL.md` and `AGENTS.md`:

1. **Preparing / updating a theme from raw style assets:**
   - Use the active `--dir` (`DIR`, `.delivery-skills` by default) — never hardcode `.delivery-skills`.
   - When the DM points to a style-assets path (e.g. a `style-guide.md` or brand folder), or when `ledger` prints a warning that `<DIR>/theme` is missing or does not match the configured path:
     - Check whether the path is already a ready-made pack (`.css` file, or directory containing `theme.css` / `theme.json`). If so, do not write into `<DIR>/theme/` (the resolver reads ready-made packs directly and ignores `<DIR>/theme/`).
     - For raw style assets (Markdown style guide, logos, brand tokens): read the assets, propose the concrete mapping to the DM (palette/font tokens, optional logo/header/footer text, and target `theme_reports`), and wait for confirmation.
     - After confirmation, write `<DIR>/theme/theme.css`, copy any chosen logo into `<DIR>/theme/`, and write `<DIR>/theme/theme.json` with `"source"` set to the canonical absolute path of the style assets — leaving the DM's source folder untouched (unless the DM explicitly asks to author a portable pack directly there).
     - Update `"theme"` (and `"theme_reports"` if requested) in `<DIR>/config.json` only from the DM's confirmation.
     - Re-run the same command with its original flags (`--dir`, `--sprint`, `--today`, `--theme`) plus `--offline` (following the existing cache/fresh-data rules) and show every warning.
   - Authoring rules for `theme.css`:
     - Override documented `:root` tokens first; add targeted class rules only where needed.
     - Preserve visibility and semantic meaning of `.private`, RAG badges, delta arrows, and `@media print` output.
     - Use system font fallbacks; do not use `@import` or non-`data:` `url(...)`; never include `</style>` or `<script>`; never put engineer names in CSS `content:` or logo assets.
2. **Prose / voice styling during report generation:**
   - Follow the **effective** theme selection for the run (accounting for `--theme PATH` and `--theme none`).
   - When proposing `## Summary` bullets (Step 5) or drafting a DM-requested `## Exec note`, if the effective theme path is a Markdown style guide or a directory containing `.md` style guide(s), treat their tone/terminology rules as reference material subordinate to Delivery Ledger's rules (no computed/quoted figures, no engineer names, never open HTML, DM confirms every line).
   - Never rewrite existing confirmed `notes.md` text merely because the visual theme changed.

  - Add `theme: str = ""` and `theme_reports: list[str] = field(default_factory=lambda: list(DEFAULT_THEME_REPORTS))` to `Config`, validated in `load_config()`.

  - Add `--theme` to `report` and `person` subparsers.
- **`ledger/render.py`**:
  - Tokenize `CSS` (`--other`, `--font`, `--font-heading`, `--mono`, `--radius-card`, `--radius`, `--max-width`) and replace hardcoded `#B8C0CA` in `_flow()` with `var(--other)` plus `.flow-bar` class (deliberately updating the literal `background:#B8C0CA` assertion in `tests/test_render.py:205`).
  - Add optional `theme: Theme | None = None` to `_page()`, `_head()`, `render_manager()`, `render_dm()`, `render_person()` (and apply brand header/logo/footer uniformly in both `_head()`/`_footnote()` and `render_person()`).

  - Strip `<style>...</style>` and the generated `.brand-logo` `src="data:..."` attribute before `unescape()` in the `manager_` name-leak scan.

## 9. Edge cases

- **No `"theme"` in `config.json` (or `"theme": ""`):** No theme loaded and no theme filesystem access, even if `<dir>/theme/` exists.
- **`theme_reports` excludes the current command's targets (e.g. `person` with default `["manager"]`, or `theme_reports: []`):** Theme filesystem access is skipped (even if `"theme"` points to a moved/missing path). Passing `--theme PATH` (non-`none`) in that state warns and skips loading.
- **Missing theme path when enabled:** Raises `ValueError` before any notes or HTML writes.
- **Relative paths when CWD != `--dir`:** Config `"theme"` resolves against `--dir`; CLI `--theme` resolves against `os.getcwd()`.
- **Raw style-asset path with no `<dir>/theme/theme.json`:** Emits a `warning:` and renders with default styling.
- **Switching `"theme"` from `/brand/acme` to `/brand/globex` while `<dir>/theme/theme.json` still records `source: "/brand/acme"`:** Canonical `realpath` mismatch emits a `warning:` and falls back to default styling.
- **Ready-made theme folder (`theme.css` or `theme.json` directly inside `"theme"`):** Loaded directly; `<dir>/theme/` is ignored.
- **CLI `--theme none`:** Disables theming cleanly for that run even if `config.json`'s `"theme"` path no longer exists.
- **Unreadable CSS/JSON/logo or a directory named `theme.css`:** Wrapped into a contextual `ValueError` before any writes (no traceback, no partial report writes).
- **CSS contains `</style>` or `</STYLE>`:** Raises `ValueError`.
- **CSS contains `@import` or relative `url(logo.png)` or `url(https://...)`:** Emits a `warning:`; `/* comment with https://... */` and `url("data:...")` do not warn.
- **Logo symlink pointing outside the selected theme directory, `../escape.png`, `https://...`, unsupported extension, or >512 KB:** Raises `ValueError`.
- **Name-leak scan edge cases on `manager_`:**
  - Engineer name in `header_note`, `footer_note`, `logo_alt`, literal visible text `data: Maya Brook`, or escaped `&lt;style&gt;Maya Brook&lt;/style&gt;` → triggers `warning: manager file mentions Maya Brook`.
  - Engineer name in a `theme.css` comment or accidentally appearing inside base64 logo `src` bytes → does not trigger a false positive.
